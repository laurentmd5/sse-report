Document de Conception Produit - Application de Suivi des Interventions FTTH
1. Introduction
1.1 Contexte du Projet
L'entreprise dispose d'équipes techniques intervenant sur le réseau FTTH (Fiber To The Home). Actuellement, les chefs d'équipe effectuent des interventions et génèrent des rapports via la plateforme Senpil Pro. Ces rapports sont imprimés au format PDF et doivent être intégrés manuellement dans des feuilles de calcul Excel pour le suivi et le reporting.

1.2 Problématique Actuelle
Problème	Impact
Saisie manuelle des données	Perte de temps et erreurs humaines
PDF non exploitables (images)	Impossible d'extraire automatiquement les données
Absence de centralisation	Difficulté de suivi et de reporting
Processus manuel	Risque d'oubli ou de données incomplètes
1.3 Objectif du Projet
Développer une application web permettant :

L'upload automatique des PDF Senpil Pro

L'extraction intelligente des données (nom du fichier + OCR ciblé)

La centralisation des données dans une base MySQL

La génération automatique des rapports hebdomadaires et mensuels

L'export des données au format Excel

3. Étude de Faisabilité
3.1 Analyse des Données Sources
3.1.1 Fichier PDF Senpil Pro
Format : PDF scanné (image), pas de couche texte

Structure :

yaml
Page 1: En-tête avec informations générales
Page 2: Détails techniques
Page 3: Formulaire client (Nom, Téléphone)
Page 4: Récapitulatif (ND, Adresse)
Page 5: Géolocalisation
Nom du Fichier : Structure standardisée

text
{ND}-{Tâche}-({INL})-{Nom Client}.pdf
Exemple : 339683059-Survey-(INL)-Serigne Mbaye Seck.pdf

3.1.2 Données Extraites
Donnée	Source	Méthode d'extraction	Fiabilité
ND (Numéro de Demande)	Nom du fichier	Parsing	100%
Tâche	Nom du fichier	Parsing + Liste autorisée	100%
Nom du Client	Nom du fichier	Parsing	95%
N° Demande (Commande)	Contenu PDF	OCR ciblé	>95%
3.2 Justification de l'Approche
Pourquoi ne pas faire de l'OCR sur tout le document ?

Critère	OCR Complet	OCR Ciblé
Complexité	Élevée	Faible
Temps traitement	5-10s	1-2s
Taux d'erreur	10-20%	<5%
Maintenance	Complexe	Simple
Coût	Élevé	Faible
Conclusion : L'approche hybride (nom fichier + OCR ciblé) est la plus adaptée.

sql
-- Table des utilisateurs
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role ENUM('admin', 'team_leader') NOT NULL,
    full_name VARCHAR(100) NOT NULL,
    team_id INT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login TIMESTAMP NULL,
    INDEX idx_team (team_id),
    INDEX idx_role (role)
);

-- Table des équipes
CREATE TABLE teams (
    id INT PRIMARY KEY AUTO_INCREMENT,
    team_name VARCHAR(50) UNIQUE NOT NULL,
    team_leader_id INT,
    description TEXT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (team_leader_id) REFERENCES users(id)
);

-- Table des interventions
CREATE TABLE interventions (
    id INT PRIMARY KEY AUTO_INCREMENT,
    nd VARCHAR(20) NOT NULL COMMENT 'Numéro de Demande',
    demande_no VARCHAR(20) COMMENT 'N° de commande (extrait OCR)',
    client_name VARCHAR(255) NOT NULL COMMENT 'Nom du client',
    task_type VARCHAR(50) NOT NULL COMMENT 'Type de tâche',
    team_leader_id INT NOT NULL,
    intervention_date DATE NOT NULL,
    pdf_filename VARCHAR(255),
    pdf_path VARCHAR(500),
    extraction_method ENUM('filename_only', 'filename_ocr', 'manual') DEFAULT 'filename_ocr',
    confidence_score INT DEFAULT 0 COMMENT 'Score de confiance 0-100',
    validation_status ENUM('pending', 'validated', 'corrected') DEFAULT 'pending',
    validated_by INT,
    validated_at TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (team_leader_id) REFERENCES users(id),
    FOREIGN KEY (validated_by) REFERENCES users(id),
    INDEX idx_nd (nd),
    INDEX idx_date (intervention_date),
    INDEX idx_team (team_leader_id),
    INDEX idx_task (task_type),
    INDEX idx_validation (validation_status)
);

-- Table de logs OCR
CREATE TABLE ocr_logs (
    id INT PRIMARY KEY AUTO_INCREMENT,
    intervention_id INT,
    page_number INT,
    raw_text TEXT,
    extracted_value VARCHAR(50),
    extraction_pattern VARCHAR(100),
    processing_time_ms INT,
    error_code VARCHAR(20),
    error_message TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (intervention_id) REFERENCES interventions(id) ON DELETE CASCADE,
    INDEX idx_intervention (intervention_id)
);

-- Table des rapports mensuels (cache)
CREATE TABLE monthly_reports (
    id INT PRIMARY KEY AUTO_INCREMENT,
    report_month VARCHAR(7) NOT NULL COMMENT 'Format: YYYY-MM',
    team_id INT,
    team_name VARCHAR(50),
    total_sav INT DEFAULT 0,
    total_diag_reor INT DEFAULT 0,
    total_installation INT DEFAULT 0,
    total_passage INT DEFAULT 0,
    total_survey INT DEFAULT 0,
    total_upgrade INT DEFAULT 0,

    total_modif_interieur INT DEFAULT 0,
    total_clients INT DEFAULT 0,
    generated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_month_team (report_month, team_id),

-- Table d'audit
CREATE TABLE audit_log (

yaml
# Correspondance entre données sources et base
source_mapping:
  filename_nd:
    field: nd
    source: nom_fichier
    validation: regex ^\d{9}$

  filename_task:
    field: task_type
    source: nom_fichier
    validation: enum [Survey, Passage, RIT, RIT + Survey, reléve, Installation]

  filename_client:
    field: client_name
    source: nom_fichier
    validation: length >= 3

  ocr_demande:
    field: demande_no
    source: pdf_content
    validation: regex ^\d{8,}$
4.4 Modules Fonctionnels
4.4.1 Module Parser
Responsabilités :

Extraction des données du nom du fichier

Validation des données extraites

Gestion des variantes de format

Règles de Parsing :

yaml
filename_patterns:
  - pattern: "^(\\d{9,})-(Survey|Passage|RIT|reléve)(.*?)-(.+)\\.pdf$"
    capture:
      1: nd
      2: task_type
      4: client_name
  
  - pattern: "^(\\d{9,})-(Survey|Passage|RIT|reléve)-INL-(.+)\\.pdf$"
    capture:
      1: nd
      2: task_type
      4: client_name
  
  - pattern: "^(\\d{9,})-(SURVEY_INSTALLATION|RIT|PASSAGE)-(.+)\\.pdf$"
    capture:
      1: nd
      2: task_type
      4: client_name
4.4.2 Module OCR
Responsabilités :

Conversion PDF → Image

Prétraitement de l'image

Extraction du numéro de demande

Pipeline OCR :

yaml
steps:
  - conversion:
      method: PyMuPDF
      dpi: 300
      format: JPEG

  - preprocessing:
      - grayscale: true
      - threshold: Otsu
      - denoise: median_blur
      - contrast: equalize_hist

  - extraction:
      method: Tesseract
      language: fra+eng
      psm: 6  # Single text block
      pattern: "/(\\d{8,})"
      target_pages: [1, 2, 3]

  - validation:
      - length: 8-10 digits
      - starts_with: allow any

6. Processus Métier
6.1 Workflow Complet
stateDiagram-v2
    [*] --> Upload: Technicien upload PDF
    Upload --> ParseFilename: Extraction nom
    ParseFilename --> ParseFilename: ND, Tâche, Client
    ParseFilename --> OCR: OCR ciblé
    OCR --> OCR: N° Demande
    OCR --> Validation: Données extraites
    
    Validation --> AutoValid: Confiance > 80%
    Validation --> ManualValid: Confiance < 80%
    
    AutoValid --> Save: Enregistrement auto
    ManualValid --> Correct: Correction manuelle
    Correct --> Save: Enregistrement
    Save --> [*]
    
    Upload --> Error: Erreur
    Error --> ManualInput: Saisie manuelle
    ManualInput --> Save
6.2 Règles Métier
Règle 1 : Format du Fichier

Le fichier doit être au format PDF

Le nom doit suivre le pattern standard

Taille max : 10MB

Règle 2 : Validation des Données

ND : 9 chiffres minimum

N° Demande : 8-10 chiffres

Nom Client : 3 caractères minimum

Tâche : Valeur dans la liste autorisée

Règle 3 : Intégrité des Données

Un ND ne peut être enregistré qu'une seule fois par jour

Le chef d'équipe ne voit que ses interventions

L'administrateur voit toutes les interventions

Règle 4 : Confidentialité

Authentification requise pour toutes les actions

Les mots de passe sont hachés (bcrypt)

Les sessions expirent après 30 minutes d'inactivité

7. Points d'Attention Techniques
7.1 Qualité des PDF
Problème	Solution
PDF de mauvaise qualité	Prétraitement OpenCV (contraste, bruit)
Rotation incorrecte	Détection et correction automatique
Pages manquantes	Avertissement à l'utilisateur
Fichier trop volumineux	Compression ou limitation taille upload
7.2 Fiabilité OCR
Problème	Solution
Lettres confondues (O/0, I/1)	Dictionnaire de correction
Caractères mal reconnus	Score de confiance + validation humaine
Plusieurs chiffres possibles	Règle de sélection (longueur, position)
Changement de format Senpil	Surveillance + mise à jour du parser
7.3 Performance
Aspect	Stratégie
Temps de traitement	Optimisation du pipeline OCR
Nombre de requêtes	Pagination des listes
Base de données	Indexation des colonnes clés
Rapports mensuels	Cache en base de données
7.4 Sécurité
Menace	Protection
Accès non autorisé	Authentification + Sessions
Injection SQL	SQLAlchemy (requêtes paramétrées)
XSS	Sanitization des entrées
Fichiers malveillants	Validation type/taille + Antivirus
Données sensibles	Chiffrement en base
